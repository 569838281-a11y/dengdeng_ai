# 灯灯相关专有词汇教学稿

> 来源：桌面 `Jieba.docx` 词表 + 灯灯实现里同样重要、但词表未写全的概念。  
> 目标：按**用途 / 功能 / 类型**整理；给出全称与中文名；用通俗话解释；并补上「Agent 实时打印工作步骤」等实战必知词。

---

## 怎么读这份稿子

可以把整条链路想成：

1. **把文档切碎、做成可搜的向量库**（分词 / 切块 / 嵌入）  
2. **问一句就去库里捞证据**（检索 / 重排 / 评测指标）  
3. **证据不够就拆问题、联网、多跳**（RAG 变体 / Agent）  
4. **生成前先评判、不够就停或再搜**（自检 / 门控）  
5. **把过程实时打给前端，并把重要事实记进记忆**（流式 / 记忆 / 人机协作）

下面按这个顺序分类。每一条格式统一为：

- **英文（全称）** · 中文名  
- 一句话通俗解释

## 一、文本预处理与切块（把长文变成可检索的小块）

| 词汇 | 全称 / 中文 | 通俗解释 |
|------|-------------|----------|
| **Jieba** | 结巴中文分词 | 把中文句子切成词（如「出场率」→「出场 / 率」），方便关键词检索和统计。 |
| **LumberChunker** | （论文方法名）智能切块器 | 按语义边界切文档，而不是死板地按固定字数切断，减少「半句话被切开」的情况。 |
| **Small-to-Big** | 小块检索 → 大块阅读 | 先用小片段精准命中，再把对应的大段上下文拿给模型读，兼顾准和全。 |
| **Late Chunking** | 迟切块 / 后切块 | 先整篇做嵌入再切，让小块仍带着全文语境，减轻「切碎后语义漂走」。 |
| **RAPTOR** | Recursive Abstractive Processing for Tree-Organized Retrieval · 树状摘要检索 | 把文档层层摘要成一棵树，既可搜叶子细节，也可搜上层概括。 |
| **Parent-Child** | 父块–子块检索 | 子块（短）负责命中，父块（长）负责给模型完整上下文；灯灯证据门控里常用这套思路。 |
| **命题级检索** | Proposition-level Retrieval | 不整段检索，而把文本拆成「一条条可独立成立的命题/事实句」再检索，命中更干净。 |
| **Dense X Retrieval** | 稠密命题检索（Dense X） | 典型的命题级稠密检索路线，和「命题级检索」常一起出现。 |
| **概念瓶颈更直** | Concept Bottleneck（概念瓶颈）思路 | 先落到少量可解释的「概念」再往下推，比端到端黑盒更直白、更好查错。 |

## 二、向量、嵌入与检索引擎（「语义相似」怎么算）

| 词汇 | 全称 / 中文 | 通俗解释 |
|------|-------------|----------|
| **BERT** | Bidirectional Encoder Representations from Transformers · 双向 Transformer 编码器 | 经典语言模型底座，很多检索/分类模型都从它演化而来。 |
| **Sentence-BERT（SBERT）** | 句向量 BERT | 把整句压成一个向量，用向量距离衡量「两句话像不像」。 |
| **E5** | EmbEddings from bidirEctional Encoder rEpresentations · 通用文本嵌入系列 | 微软系常用嵌入模型，适合检索与语义相似度。 |
| **Contriever** | 无监督稠密检索器 | 少靠人工标注就能训出的稠密检索模型。 |
| **ColBERT / Col-BERT** | Contextualized Late Interaction over BERT · 延迟交互检索 | 不是整句一个向量，而是词级向量再做 MaxSim 匹配，往往更准、也更吃算力。 |
| **MaxSim** | Maximum Similarity · 最大相似度聚合 | ColBERT 里：查询每个词找文档里最像的词，再汇总得分。 |
| **bge-m3** | BAAI General Embedding M3 · 智源多功能嵌入 | 灯灯本地常用的中英多语嵌入：同一模型可做稠密检索、多向量、稀疏信号。 |
| **BAAI** | Beijing Academy of Artificial Intelligence · 北京智源人工智能研究院 | bge 系列模型的出品方。 |
| **DPR** | Dense Passage Retrieval · 稠密段落检索 | 「问题向量 vs 段落向量」双塔检索的经典范式。 |
| **SPLADE** | Sparse Lexical anD Expansion · 稀疏词汇扩展检索 | 学出「加了同义/相关词权重」的稀疏向量，像升级版关键词检索。 |
| **稀疏检索** | Sparse Retrieval | 靠词是否出现、词频、BM25 等计分；可解释、对专有名词友好。 |
| **稠密检索** | Dense Retrieval | 靠向量相似度；擅长同义改写、换说法仍能命中。 |
| **RRF** | Reciprocal Rank Fusion · 倒数排名融合 | 把多路检索结果按排名融合，简单稳，常用于「稀疏+稠密」混合。 |
| **Rerank** | 重排序 | 初检捞很多条，再用更强模型精排 Top-K，提高「第一条就对」的概率。 |
| **RankGPT** | 用 GPT 做列表重排 | 让大模型当裁判，对候选段落排序。 |
| **monoT / monoT5** | 单塔 T5 重排器 | 经典「一段一段打分」的重排模型写法（词表里常写作 monoT）。 |
| **instructor** | Instructor Embedding / 指令式嵌入 | 嵌入时附带「任务指令」（如「用于检索」），同一模型可适配多种用途。 |
| **sentence-transformers** | 句向量工具库 | 加载、训练、推理 Sentence-BERT 类模型的常用 Python 库。 |
| **Hugging Face** | （平台/公司名） | 模型与数据集社区；常写作 HF，用来下载 bge、BERT 等。 |
| **Chroma** | ChromaDB · 向量数据库 | 存向量 + 元数据，并提供相似度查询的轻量库。 |
| **同义词词林** | 《同义词词林》类词典资源 | 中文同义词表，可做查询扩展或对齐口语说法。 |
| **OpenHowNet** | 开放知网义原资源 | 用「义原」描述词义，做细粒度中文语义/同义关系。 |

### 知识图谱嵌入（图上的「点关系」）

| 词汇 | 全称 / 中文 | 通俗解释 |
|------|-------------|----------|
| **TransE** | Translating Embeddings · 平移嵌入 | 把关系看成向量平移：头实体 + 关系 ≈ 尾实体。 |

## 三、检索质量怎么「打分」（评测指标）

| 词汇 | 全称 / 中文 | 通俗解释 |
|------|-------------|----------|
| **MRR** | Mean Reciprocal Rank · 平均倒数排名 | 正确答案排得越靠前越好；看「第一条命中有多快」。 |
| **NDCG** | Normalized Discounted Cumulative Gain · 归一化折损累计增益 | 考虑排序位置与相关性等级的综合指标，榜单评测很常见。 |
| **IsRel** | Is Relevant? · 是否相关（判定） | 二分类：这条证据跟问题相关吗？常作自动/人工标注标签。 |
| **Ragas** | RAG Assessment · RAG 评估套件 | 自动估忠实度、相关性等，用来回归「检索+生成」有没有变差。 |
| **Judge / LLM-as-a-Judge** | 大模型当裁判 | 用 GPT 等给答案打分或比优劣；方便但要防裁判自己也偏。 |
| **GPT-4o** | GPT-4 Omni | OpenAI 多模态旗舰之一，常被用作裁判或强基线。 |
| **glm / glm-5.3** | 智谱 GLM 系列 | 国产大模型家族；词表里的版本号表示某代对话/推理模型。 |

## 四、经典 RAG 与「会反思的检索」（答之前先想证据够不够）

| 词汇 | 全称 / 中文 | 通俗解释 |
|------|-------------|----------|
| **Adaptive-RAG** | 自适应检索增强生成 | 按问题难度选策略：简单直接答，复杂再多步检索。灯灯路由里有对应思想。 |
| **Self-RAG** | 自反思检索增强 | 模型自己批判「要不要检索 / 证据有没有用 / 答案能不能支撑」。 |
| **CRAG** | Corrective RAG · 纠正性 RAG | 先评判检索：Correct / Ambiguous / Incorrect，再决定用本地、补搜还是改写查询。 |
| **IRCoT** | Interleaving Retrieval with Chain-of-Thought · 检索与思维链交错 | 想一步 → 搜一步 → 再想，多跳问答常用。灯灯里的 **hop（跳）** 就来自这类流程。 |
| **Self-Ask** | 自问自答分解 | 先把自己拆成子问题，再逐个回答。 |
| **Decomposed Prompting** | 分解式提示 | 把复杂题拆成子程序式步骤，分别提示求解。 |
| **Least-to-Most** | 由易到难提示 | 先解决简单子问题，再组合攻克总问题。 |
| **Chain-of-Thought（CoT）** | 思维链 | 让模型把推理步骤写出来，而不是直接甩答案。 |
| **Chain-of-Verification（CoVe）** | 验证链 | 先答，再生成核查问题，查完再改答案，降幻觉。 |
| **Verify-and-Edit** | 验证并编辑 | 用检索证据核对后，改写原先答案。 |
| **FLARE** | Forward-Looking Active REtrieval · 前瞻主动检索 | 生成时预判「下一句可能没把握」就主动再检索。 |
| **FreshLLMs** | 新鲜度评测/数据向工作 | 关注模型知识是否过时，推动检索/联网补新。 |
| **BridgeRAG** | 桥接式 RAG | 强调「桥接实体/中间事实」才能连上多跳答案（与 Hit/Bridge/Miss 叙事相近）。 |
| **PAR2-RAG** | （论文方法名）并行/规划类 RAG 变体 | 一类强调规划与再检索的 RAG 改进（读论文时按原文设定理解即可）。 |
| **SURE-RAG / SURE** | Sufficiency-oriented RAG · 充分性导向 | 判断「当前证据是否足够支撑回答」，不够就继续搜或停。 |
| **HALT** | 证据不足则停止（声明/机制名） | 「证据撑不住就不要硬编」——灯灯门控里会走向追问或拒答。 |
| **TASR / Stop-RAG** | 停止检索相关机制 | 决定何时别再搜了，避免空转或越搜越偏。 |
| **SUPPORT** | 支持度 / 证据支持关系 | 某条证据是否支持某句断言；门控与核对常用标签。 |
| **hop** | 多跳中的一跳 | 一次「子问题 → 检索 → 中间结论」；多跳 = 多 hop。 |
| **EMNLP** | Empirical Methods in NLP · 自然语言处理经验方法会议 | 很多 RAG/Agent 论文发表的顶会之一，见到它多半是「出处」。 |
| **StonyBrookNLP** | 石溪大学 NLP 组 | IRCoT 等检索推理工作的常见作者机构标签。 |

## 五、Agent、规划与工具调用（不只检索，还会「干活」）

| 词汇 | 全称 / 中文 | 通俗解释 |
|------|-------------|----------|

| **Voyager** | 开放世界技能库 Agent（常以 Minecraft 演示） | 把学会的技能存起来复用，强调终身学习。 |

| **Outlines** | 约束解码库 | 让模型输出必须符合正则/JSON Schema 等。 |
| **Willard / Louf** | Outlines 相关作者名 | 文献或依赖里见到时，多指向约束解码工具链，不是新算法缩写。 |

| **Personalized PageRank** | 个性化网页排名 | 从种子节点在图上扩散相关性，找紧密关联的邻居事实。 |
| **LoCoMo / LongMemEval** | 长对话记忆评测基准 | 专门考「隔了很久还能不能记住」。 |

## 七、对话状态与改写（多轮聊天专用）

# 十、词表没写全、但实现「Agent 实时打印工作步骤」必知（强烈建议掌握）

这一节专门补你点名的能力：**看着 Agent 一步步工作**，以及灯灯里成套的门控词。

## 10.1 实时打印工作步骤

| 词汇 | 中文名 | 通俗解释 |
|------|--------|----------|
| **ReAct 轨迹（Thought / Action / Observation）** | 思考 / 行动 / 观察 | Agent 每一步的标准三元组；前端字幕往往就在打印这些。 |
| **`note_thought` / `note_read` / `note_edit`** | 记下思考 / 读到的材料 / 编辑动作 | 灯灯把步骤写入「思考流」，供 UI 实时展示。 |
| **`react_stream` / `streaming` / `stream_prompt`** | 流式 ReAct / 流式提示 | 边生成边推送，而不是等整段结束才一次性返回。 |
| **SSE 事件 / event stream** | 事件流 | 一条条 JSON 事件：`thought`、`read`、`answer`、`confirm`… |
| **Orchestrator / Supervisor（主管）** | 编排器 / 主管专员 | 决定下一步派谁：检索员、冲浪员、成文员、对战员。 |
| **WebSurfer / FileSurfer / Coder** | 网页冲浪员 / 文件员 / 代码员 | Magentic 风格专员；各自 `note_thought("WebSurfer")` 一类打点。 |
| **tool call / function calling** | 工具调用 / 函数调用 | 模型输出「要调哪个函数、参数是什么」，运行时真的去执行。 |
| **Observation** | 观察结果 | 工具返回的原文/摘要，再喂回模型继续想。 |
| **progress / live_feed** | 进度 / 直播馈送 | 面向用户的进度条或直播式状态（「正在搜图鉴」「正在核对」）。 |
| **cancel / abort** | 取消 | 长任务可中断，避免 Agent 空转。 |

## 10.2 灯灯证据与路由（和 CRAG / Self-RAG / SURE / HALT 对齐的实现词）

| 词汇 | 中文名 | 通俗解释 |
|------|--------|----------|
| **Hit / Bridge / Miss** | 命中 / 桥接 / 未命中 | 证据直接能答 / 只够当跳板 / 完全不够。 |
| **Correct / Ambiguous / Incorrect（CRAG）** | 正确 / 含糊 / 错误 | 对整次检索质量的三档判决，决定用库、补搜还是改写。 |
| **evidence_gate** | 证据门控 | 生成前的闸门：不够格就别说满话。 |
| **evidence_slots** | 证据槽位 | 把问题拆成必须填满的空位（谁、属性、数值…），槽满才答。 |
| **need_local / need_web / need_ask / speak** | 要本地库 / 要联网 / 要追问 / 可开口 | 主管路由的几扇门。 |
| **catalog / catalog grounding** | 图鉴目录 / 目录锚定 | 精灵名等必须以图鉴实体为准，防止「假 Hit」乱认冠军。 |
| **false Hit** | 假命中 | 检索分高但实体/事实不对；必须靠目录与门控拆穿。 |
| **appearance_rate_top1** | 出场率第一名（谓词） | 写入 archival 的结构化事实键，需要时再召回。 |
| **persona_story / story_read** | 人设故事 / 读故事页 | 「灯灯是谁」走故事页，不和图鉴伤害混答。 |
| **lived memory / turn memory / admitted memory** | 经历记忆 / 回合记忆 / 已确认记忆 | 分寿命与可信度：刚说过的、跨会话的、用户确认过的。 |
| **job ledger / job state** | 任务台账 / 任务状态 | 配队、对战等长任务的进度账。 |
| **speech_review** | 话术审查 | 开口前检查是否触犯玩家禁忌、是否超证据。 |
| **write_gate / write_confirm** | 写入门 / 写入确认 | 改仓库等副作用必须人点头（Human-in-the-loop）。 |
| **intent_judge / follow_agent** | 意图判断 / 追问改写员 | 判断用户想干嘛；把「那它呢」收成独立问句再检索。 |
| **page_calc / MCP 计算器** | 页面/工具计算器 | 可选的精确伤害等计算工具；与目录里的公式结论分工。 |
| **prefer-site** | 优先站点 | 联网时优先信任的域名列表（官方/图鉴站）。 |
| **KV-cache / kv_blocks** | 键值缓存块 | 复用已算过的 Transformer 状态，加快多轮与长上下文。 |

## 10.3 训练与推理开关（读灯灯配置时）

| 词汇 | 中文名 | 通俗解释 |
|------|--------|----------|
| **encoder / 冻结编码器** | 嵌入编码器 | 负责把文本变向量；「冻结」= 不再重新训练/改权重。 |
| **re-embed** | 重新嵌入 | 改了切块或模型后重算全库向量；成本高，需显式决策。 |
| **`_use_lora`** | 是否启用 LoRA 成文 | 开关成文风格适配；关闭则走基座模型口吻。 |

# 十二、建议的学习顺序（一条周末路径）

1. **检索底座**：Jieba → bge-m3 → 稀疏 vs 稠密 → RRF/Rerank → MRR/NDCG  
2. **RAG 升级**：Parent-Child → Adaptive-RAG → CRAG → Self-RAG → IRCoT/hop  
3. **门控四件套**：SUPPORT → SURE → HALT → Hit/Bridge/Miss  
4. **Agent 可视**：ReAct 三元组 → `note_thought` → SSE 流 → Supervisor 派工  
5. **记忆**：persona / archival / ledger → MemGPT 换入换出直觉  
6. **工程**：FastAPI、MCP、Pydantic、Human-in-the-loop  

读到某一节时，若只想抓「灯灯在干什么」，看 **第十节 + 第十一节** 就够用；若要对齐论文原文，再回前八节查全称。
