> **写给谁看**

> - AI / NLP 方向学生：听到某个技术名，能马上联想到「模型可能在犯哪类错」。

## 开篇：灯灯到底要做成什么

想象你在和一个叫「灯灯」的双灯鱼聊天。她说话要可爱、要像灯灯，但**数字和名单不能靠她「感觉」**——否则会出现：

- 随便报一个种族值；
- 配出六只根本不在仓库里的精灵；
- 把微信标题里的形容词当成精灵名字。

所以产品原则从一开始就是：

| 谁来做 | 做什么 | 为什么 |
|--------|--------|--------|
| **程序** | 选六人、算伤害、核对规则、读写仓库 | 可复现、可审计、不会「今天一个数明天另一个」 |
| **大模型** | 听懂你在问什么、决定下一步查哪、把结果说成灯灯的话 | 自然语言灵活，但不可当真理源 |
| **知识库 / 网页** | 提供原文证据 | 名录是权威；网页是可作废的线索 |

玩家气泡里还规定：不能出现「文件、MCP、API、JSON、代码、数据库」——灯灯是宠物助手，不是运维手册。

### 灯灯要会的几件事（产品清单）

| 能力 | 玩家真实体验 | 背后怕什么 |
|------|--------------|------------|
| 智能配队 | 「帮我排一套打火队」→ 给出六人与配招 | 模型瞎点名、把对手塞进己方 |
| 查图鉴 | 「水灵种族值多少」 | 网页二手攻略覆盖官方名录 |
| 模拟对战 | 「水灵打霹雳迪迪谁赢」 | 胜负靠模型嘴炮 |
| 伤害链 | 「出场率最高的那只用最大招打水灵多少伤」 | 一环假名，后面全错 |
| 跨轮记忆 | 刚说过谁第一，再问「最高是谁」应记得 | 每问都当新会话；或把上一只精灵粘到无关问题 |
| 讲自己的故事 | 「讲讲你成长」 | 去讲海豹船长的图鉴 |

贯穿后期调试的「魔鬼原题」是：

> 闪耀大赛出场率最高的精灵，用它威力最大的技能，打天真性格 / 开了水泡盾应对的水灵，能打出多少伤害？

你把它拆开就会发现，这不是一道题，而是一条流水线：

```text
外面的「谁出场最多」
  → 必须落成「名录里真实存在的一只精灵」
    → 再找它技能池里威力最大的那招
      → 再看水灵属性 / 规则
        → 最后用本地伤害公式算数字
```

**任意一环把「看起来像答案的字符串」当成真理，整条链都会一本正经地错下去。** 后面所有阶段，几乎都在跟这种「一本正经的错」较劲。

## 架构鸟瞰（先建立地图，名词后面阶段再展开）

可以把灯灯想成一家小店：

- **店长（监督者 `supervisor`）**：不亲自翻书，只决定「下一步谁干活、干什么」。
- **资料员（`fact_read`）**：只翻店里的名录和规则本。
- **探查员（`web_read`）**：去外面网上找报纸，但报纸可以作废。
- **对战员（`battle_agent`）**：按公式算数。
- **成文员（`dengdeng_reply`）**：把结果说成灯灯的话，并过一遍「像不像灯灯」的检查。
- **账本（`job_ledger`）**：所有人只往同一本账上写，工人之间不私聊。

```text
你（浏览器）
  → 总台 pipeline：先听你在干嘛（意图）
    → 店长 supervisor：派工
         ├─ 资料员：本地名录
         ├─ 探查员：网页（要过「能不能当结论」的闸）
         ├─ 记忆柜 lived_memory：跨轮可召回的事实
         ├─ 故事本 story_read：只讲灯灯自己
         └─ 成文：开口给玩家
```

调度词就像店长喊话：`need_local`（先查名录）、`need_web`（去上网）、`need_ask`（问客人）、`speak`（可以回答了）。

## 术语速查：听到名字时，先想到「模型在犯什么病」

读时间线前，先把几块「听诊器」放桌上。后文出现这些名字时，回来对一下。

| 你听到 | 人话版含义 | 典型病症（模型/系统在干什么） |
|--------|------------|------------------------------|
| **幻觉（hallucination）** | 说得流畅，但事实是编的 | 报不存在的种族值、发明技能名 |
| **意图漂移** | 把 A 类问题听成 B 类 | 伤害链被听成「帮我配队」 |
| **检索噪声** | 搜到的文章相关但不回答问题 | 搜出场率，打开的是「前十阵容抄作业」 |
| **假 Hit** | 系统以为「对上了」，其实对错了 | 把标题「第一稳稳克制凡鹰」当成精灵名 |
| **证据角色错位** | 用「成员名单」填「冠军」空格 | 阵容里出现海豹船长 → 宣布它出场率第一 |
| **半证据收束** | 证据只够讲一半，却给出最终结论 | 只看见一招有威力，就宣布「最大」 |
| **上下文污染** | 上一轮实体粘到这一轮无关问题 | 问灯灯成长，却去讲海豹船长 |
| **RAG** | 先检索再生成，用外部文档补知识 | 减轻「靠参数记忆背设定」 |
| **Agent / 工具调用** | 模型不只聊天，还能决定调哪个程序 | 决定查名录还是上网 |
| **IRCoT** | 想一步、查一步、再想下一步 | 避免一口气编完整答案 |
| **CRAG** | 先评价检索质量：对 / 糊 / 错，再决定用不用 | 糊的阵容文不能直接当冠军 |
| **Self-RAG** | 生成时自我检查：要不要检索、证据支不支持我说的 | 不支持就改口或追问 |
| **Parent–Child** | 小段定位、大段（或全池）再比 | 防「只看见冰山一角就比较」 |
| **MemGPT / archival** | 记忆分「手头」和「档案柜」，按需抽出 | 防整段对话糊进下一问造成串台 |

## 时间线：我们如何一步步被现实揍、再一步步加闸

### 阶段 0：底座——先别让模型既当裁判又当球员

#### ① 实景困境

如果做一个「什么都问 ChatGPT」的洛克助手，玩家很快会遇到：

- 「水灵物攻多少？」——模型给一个听起来合理的数，但和名录对不上；
- 「帮我配六人」——六只名字很帅，仓库里一只都没有；
- 明天再问同一句，数字又变了。

#### ② 用人话翻译问题

这不是「模型不够聪明」，而是**你把不可靠的生成器当成了数据库**。  
大模型擅长语言；**权威数值必须外置**。

#### ③ 技术名与「模型病」

- **Tool-augmented LLM（工具增强语言模型）**：模型负责理解与调度，具体查表/算数交给程序。  
  → 听到这词，先想：系统是否还在让模型「直接报数字」。
- **RAG（检索增强生成）**：先查文档再答。  
  → 听到这词，先想：答错是「没检索」还是「检索到了但用错」。

#### ④ 怎么改；为什么不用别的

| 做法 | 说明 |
|------|------|
| 我们采用 | 名录 JSON + 规则 `rules.md`；配队 `propose_team_line` 程序选人；对战 `battle.py` 结算；模型只调度与口吻 |
| 备选 A：纯聊天机器人 | 放弃。不可审计，无法对玩家负责 |
| 备选 B：让模型输出六人 JSON 再校验 | 部分团队这么做；我们更狠——**选人本身就不交给模型**，减少「生成后再补洞」的复杂度 |

#### ⑤ 效果

三种模式能跑；名录内查询稳定。后面所有「假 Hit」「串台」都是在这底座上长出来的进阶病，而不是推翻底座。

### 阶段 1：原题跑不通——听错意图、搜错引擎、前端先放弃

#### ① 实景困境

玩家问那道「出场率最高…打多少伤害」。气泡里可能出现：

- 灯灯开始「配队」或「问谁赢」——完全跑题；
- 或者去上网了，但搜到的源很差，卡住很久；
- 前端提示「检索超时」，其实后端还在翻网页。

#### ② 用人话翻译问题

一条复杂问句，被系统拆错了「今天办哪一类业务」。  
再叠加：联网源不稳、多跳本来就慢，UI 却用短超时宣判死亡。

#### ③ 技术名与「模型病」

- **意图分类 / 路由**：把自然语言映射到业务技能。  
  → 病症名：**意图漂移**——表面有「打」「精灵」，被收成 battle/lineup。
- **按需检索（Self-RAG 里的 retrieve 决策）**：有的题必须查外部，有的不用。  
  → 病症：该查的不查，或不该查的乱查。

#### ④ 怎么改；为什么不用别的

| 做法 | 说明 |
|------|------|
| 我们采用 | 出场率+伤害链 **强制 search**；换更稳的搜索引擎；链上锁定工具；前端 deadline 加长 |
| 备选：缩短超时、直接报错 | 只是把长任务伪装成失败，问题仍在 |
| 备选：一律先配队 | 会彻底毁掉伤害链 |

#### ⑤ 效果

系统终于能走到「名录没有出场率 → 去上网」。  
但「上网之后信了什么」还没管——假 Hit 的大戏从下一阶段开始。

### 阶段 2：别让店长一次安排全天——改成「想一步、查一步」

#### ① 实景困境

早期监督者容易「先把整题想明白，再一口气派很多人」。结果是：

- 中间某步已经歪了，后面工人还在按歪计划干；
- 思考流又长又糊，超时更多；
- 你无法指出「到底第几跳错了」。

#### ② 用人话翻译问题

多跳问题（要先 A 再 B 再 C）如果一次性生成完整答案，模型会**跳步脑补**。  
人肉推理也是一步一查；系统却想「写一篇完整作文」。

#### ③ 技术名与「模型病」

- **IRCoT（Interleaving Retrieval with Chain-of-Thought）**：推理与检索交错——想一小步，查一小步，再想。  
  → 听到 IRCoT，先想病症：**跳步幻觉 / 计划与证据脱节**。
- **多智能体编排（如 Magentic-One 外环 + ReAct 工人）**：有人计划，有人执行工具。  
  → 病症：**综合过度**——计划太满，执行无法纠偏。

#### ④ 怎么改；为什么不用别的

| 做法 | 说明 |
|------|------|
| 我们采用 | 每步只带当前子问题 `hop_fact`；查完再 `next_fact` 写下一句；链上工具白名单 |
| 备选：一次塞满检索结果让模型写长答案 | 无法对「单跳」做证据闸；错了也不知道错在哪跳 |
| 备选：写死固定 4 步流水线 | 「只问最高是谁」会被多余步骤拖死或乱问 |

#### ⑤ 效果

多跳变得可观测、可中断。后面 Bridge、HALT 都依赖「hop 列表」这本流水账。

### 阶段 3：网上全是「抄作业阵容」，没有「第一是谁」——Bridge

#### ① 实景困境

搜「闪耀大赛出场率」，打开的常常是：

> 《前十阵容大揭秘，抄作业指南》——榜九的毒队很强……

文章里**没有**「出场率最高的是霹雳迪迪」。  
系统若直接放弃，玩家觉得灯灯没用；若看见文中冒出「海枝枝」就宣布她是第一——那就是假 Hit。

#### ② 用人话翻译问题

检索结果**相关但不充分**：话题对了，答案槽是空的。  
你需要「再问一句」：这支队里都有谁？——而不是假装已经知道冠军。

#### ③ 技术名与「模型病」

- **检索噪声 / 相关≠足够**：搜对了主题，没填对槽。  
- **槽位填充（slot filling）**：答案里有空格（冠军名、成员列表），要用证据填。  
  → 病症：**拿错材料填空格**（用阵容名单填冠军格）。
- **CRAG 的 Ambiguous**：材料模糊时不要当 Correct 用，要纠错动作。  
  → 听到 CRAG，先想：系统有没有「对检索结果打分再决定用不用」。

#### ④ 怎么改；为什么不用别的

| 做法 | 说明 |
|------|------|
| 我们采用 | 三态 **Hit / Bridge / Miss**；Bridge 后追问「〔队〕出场精灵」；只有「最高/榜首是〔名〕」才 Hit |
| 备选：只信官方 Wiki | 出场率往往不在 Wiki 稳定更新 |
| 备选：让模型读阵容文猜谁第一 | 猜得再像也无法对玩家负责 |

#### ⑤ 效果

能从「阵容文」走进「再查成员」。  
但若下一步把成员列表里的第一个名录名升成冠军——仍会假 Hit（阶段 7 才钉死）。

### 阶段 4：只看见一座冰山尖，就评「最高的山」——半池与 Parent–Child

#### ① 实景困境

问「本系哪个技能威力更高」。系统只检索到一两行带「威力」的技能，就宣布某招最大；  
或者把外系大招（如升龙咆哮）混进比较——玩家会觉得灯灯「翻书翻漏了还嘴硬」。

#### ② 用人话翻译问题

**比较类问题**依赖「集合尽量完整」。  
你只看到全集的子集，却输出全集上的 argmax——这在统计学里叫胡来，在产品里叫假权威。

#### ③ 技术名与「模型病」

- **Chunking（切块）过细**：检索命中太碎。  
  → 病症：**以偏概全**。
- **Parent–Child RAG**：子块负责定位「是哪只、哪类」，父块/全池负责「拿全了再比」。  
  → 听到 Parent–Child，先想：系统是否「定位用小、决策用大」。
- **充足性（sufficiency）不足**：相关片段在，但不够支撑结论。  

#### ④ 怎么改；为什么不用别的

| 做法 | 说明 |
|------|------|
| 我们采用 | 本系比较只取同属性攻击段；全池比较先升格技能池；不够就说「不敢比威力」 |
| 备选：向量 Top-1 技能直接比 | 几乎保证假最大 |
| 备选：每次把全技能表塞进提示词 | 贵、慢，且仍缺少「够不够」的显式判定 |

#### ⑤ 效果

本系比较可回归正确路径；半池会拒答而不是硬嘴。

---

### 阶段 5：不能再「一个坏例加一条禁词」——开口前验收

#### ① 实景困境

你修了「海枝枝假第一」，明天标题换一种写法又炸。  
或者证据只查到出场率，伤害还没算，灯灯已经开始「告诉玩家怎么算」——随后人设审查觉得不像灯灯 / 对不上资料，最后掉进兜底句「灯灯没听清」。

玩家感受是：**前面思考了半天，最后一句装傻。**

#### ② 用人话翻译问题

需要一层「出门检查清单」：这道题答应哪些 claims？现在 hop 盖住了几条？  
不够就问人，而不是先说再后悔。

#### ③ 技术名与「模型病」

- **Self-RAG**：检索与生成带自我批判（要不要查、支不支持、好不好）。  
  → 听到 Self-RAG，先想病症：**无支持的断言**、**该查不查**。
- **SURE 式三态 support / partial / insufficient**：证据对当前子问题够不够。  
  → 病症：**半证据收束**。
- **HALT 式 claim 覆盖**：原问拆成必答点，点不齐就停。  
  → 病症：**答了一半就交差**。
- **「相关 ≠ 足够」（Q-CARE 类直觉）**：搜到了不等于能结案。

#### ④ 怎么改；为什么不用别的

| 做法 | 说明 |
|------|------|
| 我们采用 | `evidence_gate`：契约、充足性、HALT、critique；监督者开口前再跑一遍 |
| 备选：换更大模型靠自觉 | 不可复现，评审无法验收 |
| 备选：规定「没有伤害数字不许开口」 | 会堵死合法拒答（例如性格未写入公式时只能说明算不出） |

#### ⑤ 效果

不齐则 `need_ask`；「不敢比 / 还缺」可以是合格结局，而不是失败兜底。

### 阶段 6：假 Hit 第一类——把形容句、微博昵称当成精灵

#### ① 实景困境

标题：

> ……第一稳稳克制凡鹰。

系统切出「稳稳克制凡鹰」，当成出场率冠军，去查「它的属性 / 技能」。  
或桥跳读到微博标题「是小小贰哦」，下一跳变成「小小贰哦的属性」。

玩家看着思考流会笑，然后失去信任。

#### ② 用人话翻译问题

**字符串长得像答案，并不是知识库里的实体。**  
「是」后面跟的不一定是精灵名；「第一」后面跟的不一定是专有名词。

#### ③ 技术名与「模型病」

- **实体链接 / Entity Grounding**：把文本指称绑定到知识库 ID。  
  → 听到 grounding，先想病症：**表面字符串未落地**。
- **CRAG Incorrect**：检索内容不该支撑该结论 → 丢掉。  
- **Self-RAG「不支持则不断言」**。

#### ④ 怎么改；为什么不用别的

| 做法 | 说明 |
|------|------|
| 我们采用 | 冠军名必须在名录中**整段等于**某只精灵；描述性切片直接空；非名录「是 XX」不当冠军 |
| 备选：只禁「克制」「稳稳」等词 | **专题补丁**——换「稳稳压制凡鹰」又炸 |
| 备选：名录没有就 Wiki 模糊搜 | 容易从「稳稳克制凡鹰」里吸出「凡鹰」当冠军，另一种假 Hit |

#### ⑤ 效果

描述标题、微博昵称不再进入冠军槽；同型应用例测试锁住。

---

### 阶段 7：假 Hit 第二类——「队里有它」被说成「它第一」（海豹船长）

#### ① 实景困境

假名「小小贰哦」已经被闸住了。思考流变成：

- 读到阵容桥：榜九的毒队；
- 再查成员，页里出现名录精灵「海豹船长」「霹雳迪迪」；
- 系统写道：「出场率最高的精灵是海豹船长」；
- 接着一本正经算它的最大招打水灵——招式还可能张冠李戴。

这比微博昵称更危险：**名字是真的，结论是假的。**

#### ② 用人话翻译问题

证据角色是「成员列表」，槽位却是「冠军」。  
真实体 + 错误命题 = 高质量幻觉（听起来最可信的那种）。

#### ③ 技术名与「模型病」

- **Evidence–slot mismatch（证据–槽错位）**。  
  → 听到这词，先想：材料类型和空格类型是否一致。
- **CRAG Ambiguous**：有成员、无冠军句 → 只能填成员槽或问人，**禁止升格**。  
- **IRCoT 槽绑定**：这一跳的检索只允许服务这一跳的槽。

#### ④ 怎么改；为什么不用别的

| 做法 | 说明 |
|------|------|
| 我们采用 | `evidence_slots.crag_rate_champion`：阵容页 → Ambiguous；只有「最高是〔名录〕」→ Correct；禁止 `members[0]` 当冠军；问「看到甲乙丙，还不敢认定谁最高」 |
| 备选：白名单「哪些精灵可以当冠军」 | 仍是专题，且回避「证据角色」问题本身 |
| 备选：列出成员就算回答完毕 | 对玩家撒谎——他问的是「最高是谁」，不是「队里有谁」 |

#### ⑤ 效果

成员页不再制造冠军 Hit；会话停在诚实的「不敢认定」。  
**这是「假 Hit」问题的类级解法，而不是又一个标题黑名单。**

---

### 阶段 8：刚答过却失忆；问成长却讲海豹——记忆与路由

#### ① 实景困境

同一会话里：

1. 好不容易（或错误地）说到「出场率最高是某某」；  
2. 玩家再问「闪耀大赛出场率最高的是谁」——灯灯又去桥跳微博；  
3. 玩家问「你能讲讲你成长的故事吗」——思考流变成「你好像对海豹船长的过去很好奇」，去翻海豹船长图鉴，再用灯灯口吻硬圆。

玩家感受：**相关的记不住，无关的忘不掉。**

#### ② 用人话翻译问题

两件事叠在一起：

1. **记忆柜的抽屉标签太窄**：只记得「某只的属性/技能」，不记得「出场率第一是谁」这种谓词事实。  
2. **技能箱少了一格**：没有「讲自己的故事」技能，系统只能滥用「查资料」，再被历史里的精灵名带跑。

#### ③ 技术名与「模型病」

- **MemGPT / Letta（core + archival）**：手头只放一点；档案柜按需检索。  
  → 听到 MemGPT，先想病症：**上下文窗口当唯一记忆** → 串台或遗忘。
- **记忆模式（schema）过窄**：抽事实的正则/字段不覆盖某类结论。  
  → 病症：**写不进柜 / 召不回来**。
- **意图缺失 / 工具不完备**：没有对应 skill。  
  → 病症：**拿锤子打所有钉子**（一切都 search）。
- **追问改写污染**：把短句扩写时注入历史实体。  
  → 病症：**上下文污染**。
- **Self-RAG「按需检索」**：讲自己的故事不应硬检索图鉴。

#### ④ 怎么改；为什么不用别的

**B. 出场率进档案柜（谓词记忆）**

| 做法 | 说明 |
|------|------|
| 我们采用 | 写入 `appearance_rate_top1`；再问「最高是谁」按谓词召回，可零次网页 |
| 备选：每次把全文对话塞进 prompt | 串台更严重，又贵 |
| 备选：只记问句里的精灵名（turn 卡） | 记不住答案侧的冠军 |

**C. 人设故事专路由**

| 做法 | 说明 |
|------|------|
| 我们采用 | `persona_story` → 只读 `knowledge/stories/灯灯.md`；禁止改写注入名录名 |
| 备选：SYSTEM 里写「你是灯灯」让模型编 | 无依据，每次不一样 |
| 备选：故事与精灵混在一个检索库 | 相似度会被刚聊过的精灵页打赢 |

#### ⑤ 效果

Correct 的冠军可以「灯灯记得」；成长问题走故事本。  
与阶段 7 合在一起：假冠军更难写进记忆，串台源头也更少。

---

### 阶段 9：方法论觉醒——拒绝「修好这一题」

#### ① 实景困境

开发者（也包括 AI 助手）很容易：

- 看见「稳稳克制」就禁这两个字；  
- 看见微博名就加一条测试；  
- 然后在周报里写「已修复」。

下一周换个标题，同类事故再来。用户会问：你是在做产品，还是在打地鼠？

#### ② 用人话翻译问题

**个例补丁 ≠ 类级能力。**  
AI 应用的验收必须回答：同型障碍是否一起消失？

#### ③ 技术名与「模型病」

- **Invariant / 类级评测**：用「问题类 + 变体集」而不是单条样例当合同。  
  → 听到「只修了 demo」，先怀疑：**过拟合到某一句用户日志**。

#### ④ 怎么改；为什么不用别的

| 做法 | 说明 |
|------|------|
| 我们采用 | A 槽与 CRAG / B 谓词记忆 / C 故事路由；每类附论文锚点与多变体测试 |
| 备选：继续堆正则与禁词 | 不可扩展，无法向专业评审证明 |

#### ⑤ 效果

后续改动有拒绝标准：说不清「问题类 / 论文锚点 / 变体测试」的补丁，视为不合格。

| 玩家看见的翻车 | 先怀疑的病 | 应脱口而出的技术 | 灯灯里看哪里 |
|----------------|------------|------------------|--------------|
| 数字、名单靠嘴编 | 幻觉当数据库 | Tool-augmented LLM + 外置 KB | `pokemon_kb` / `battle` |

| 一次答完多跳却中间全是脑补 | 跳步幻觉 | IRCoT | `fact_read.next_fact` / `cycle_graph` |
| 搜到抄作业文就结案或乱认第一 | 相关≠足够；槽填错 | CRAG Ambiguous；slot filling | `web_read` Hit/Bridge |
| 只看见一招就说最大 | 以偏概全 | Parent–Child；充足性 | `_pool_power_bundle` / gate |

| 「稳稳克制凡鹰」「小小贰哦」当精灵 | 未实体落地 | Grounding；CRAG Incorrect | `_ground_sprite_name` |

## 还没填上的坑（避免读完以为「已经完美」）

1. **性格、水泡盾进公式**：名录板块 M 若没写，程序就不该假装算进了——这是**知识缺口**，不是调度能补的。  
2. **出场率权威源**：若没配置千岛 / 可靠 UP 主域名为优先站，系统会更多停在「不敢认定」，而不是稳定 Correct。  
3. **名录外的真精灵**：目前 Correct 强依赖本地名录；Wiki 标题全等补体能增强，但要防模糊匹配再造假 Hit。  
4. **会话记忆落盘**：测试与真实 sid 可能互相污染，工程上要 `clear_memory` 纪律。

---

## 结语：这门课真正想教的事

灯灯的迭代不是「换一个更会聊天的模型」，而是反复确认：

> **模型会流畅地错；产品必须在错变成玩家伤害之前，用结构把它拦住。**

入门开发者若只记住一句话，请记住：

- 先区分「语言问题」和「真理问题」；  
- 真理问题用程序、闸门、记忆模式、技能完备性解决；  
- 每一个技术名词背后，都对应一种你已经在实景里见过的病。

专业学生若只记住一张表，请用上面的「现象 → 病 → 技术」表当听诊器：  
**听到技术名，先激活病症；看到病症，再想起该用哪把闸。**

专题禁词只能赶走一只虫；**类级不变式 + 论文锚点 + 变体测试**才能让同型障碍一起退出舞台。
