# 现状

工具通道已改为 MCP 与提示词 Function Calling，见 `docs/mcp-fc.md`。下面第 1、2 节仍说明聊天底座。第 3 节的「没有 MCP」只描述改动之前。

## 1. 是不是接了两个大模型 API

是。`LLM_PROVIDER` 选智谱或 DeepSeek。`FallbackLLMProvider` 在主供应商失败时切到备用。这是同一套 Chat 调用换底座，不是接了两个业务工具。

## 2. 中间除了加一条配置，还做了什么

工作在 `llm_provider.py`，不是只改环境变量：

- `BaseLLMProvider` 把调用收成统一的 `invoke`
- `ZhipuProvider` / `DeepSeekProvider` 各自接 SDK、`base_url` 和型号
- 智谱评测把 temperature 截成两位小数
- 超时和重试：政策链 `get_llm_provider` 用 `LLM_TIMEOUT`（默认 60 秒）和 `LLM_MAX_RETRIES`（默认 3）；成文 `get_team_invoke` 用 `TEAM_LLM_TIMEOUT`（默认 45 秒），口吻等待至少再放到 `VOICE_LLM_TIMEOUT`（默认 120 秒），且只重试 1 次
- 成文送的是 SystemMessage 加 HumanMessage；意图规划只送一段短 JSON 提示

没有向模型提交 `functions[]` 工具描述，也没有 MCP Server。本地精灵资料、规则和伤害结算都是程序直接调用，模型看不到它们的 schema。检索、配队、对战都不走天气类第三方工具。

## 3. Agent 架构是什么，有没有 MCP

```text
React → FastAPI jobs → 规则程序（查表 / 选人 / 算伤）→ compose（LoRA 或教师聊天补全）→ 校验回退 → 气泡
```

没有 MCP Host、Client、Server，没有 `tools/list`，没有 `tools/call`。和 MCP 教材的对应关系：现在是传统后端自己调代码，最后再问模型说话。

本期不把名册或试场做成 MCP。原因：用户能看见的句子不能出现工具名和读文件这类说法；名册只有本地一份；伤害结算已经在进程里。规则看见条件就调用本进程函数，不让模型编工具名，也不给智谱或 DeepSeek 加 `functions` 参数。
